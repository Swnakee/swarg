# Module config (`App/internal/config`)

Purpose: load and validate the swarg config file (`config.json` in `Dir()`). Stdlib only.

API:
- `Provider{Type, BaseURL, Model, ContextLimit, ContextLimits, MaxTokens, APIKeyEnv, ExtraBody, Thinking, ThinkingMaxTokens}` - one model server (JSON tags as in the file).
- `Provider.ContextLimits map[string]int` (JSON `context_limits`, omitted when empty) - per-model context limit, model id -> tokens, each value > 0 (checked for the active provider). Not set in `Defaults()`.
- `(Provider) LimitFor(model string) int` - the limit of one model: the file's `context_limits` entry, else the built-in table `defaultLimits` (the Qwen3.5 ids `0.8B`/`2B`/`4B`/`9B` `-4bit` and the fine-tunes `Huihui-Qwen3.5-4B-...-4bit`, `MiMo-V2.6-Distill-Qwen-9B-OptiQ-4bit` -> 32768), else `ContextLimit`.
- `Agents{Disabled, MaxParallel}` (JSON `agents`, R-120..R-122) - `disabled` names agent types switched off (written by `/agents`, to the global file by default, R-128), `max_parallel` 1..4 (default 4) = agents at once overall. `Provider.MaxParallel` (`providers.<p>.max_parallel`, 0..4) and `Provider.Parallel()`: requests of agents at once on that Source, default 1 for `openai`/`ollama` and 4 for `openrouter`.
- `Tasks{MaxDepth, MaxSteps, MaxPerTurn}` (JSON `tasks`) - the Task mode limits (nested sub-tasks of the agent): defaults 8, 15, 8. `max_depth` 0..8 (0 = Tasks off), `max_steps` 1..200, `max_per_turn` 1..50. A partial object keeps the other defaults.
- `Prompt{WarnShare, Profile, Profiles}` - prompt settings: `warn_share` default 0.25; `profile` (`compact|standard|full`, "" = compact) and `profiles` (model pattern -> profile; `*` any run, `?` one character, case ignored) are the Prompt Profile defaults (R-116). `Provider.Profile` (`profile`) is a Source's default. `(Config) ProfileFor(provider, model) string` = longest matching pattern, else the provider's, else `prompt.profile`, else `DefaultProfile`; `ProfileNames` lists the names (kept equal to `prompt.Profiles` by a test in cmd/swarg). `Validate` / `Provider.Validate` refuse a bad name with the known ones (`profile.go`).
- `Tools{Disabled, MaxSteps, ShellTimeoutSec, AutoApprove}` - tool settings (JSON `tools`), defaults `[]`, 50, 120, false.
- `Web{Confirm, SearxURL, AllowPrivate, TimeoutSec}` (JSON `web`) - web tools: defaults true, "", false, 15; `timeout_sec` 1..120, `searx_url` empty or an http(s) URL; `confirm: false` frees `web_search`/`web_fetch` from approval (R-45); `allow_private` lets `web_fetch` reach private addresses (R-47).
- `Session{Save, Keep, Trace}` (JSON `session`) - defaults true, 50, true. `Context{AutoCompact}` (JSON `context`) - default 70; 0 = off, otherwise 50..95.
- `Skills{Disabled}` (JSON `skills`) - Skill names switched off (R-84); unknown names are a warning of the skills package, not a config error.
- `MCP{Confirm, Servers map[string]MCPServer}` (JSON `mcp`): `confirm` default true (an MCP tool asks for approval like shell unless the server is trusted and the tool read-only, R-87); `MCPServer{Command, Args, Env, URL, Headers, Disabled, Trust, Tools, TimeoutSec}`: exactly one of `command`/`url` (stdio program or Streamable HTTP endpoint), `env` and `headers` values go through `os.ExpandEnv` (name a secret, never write it; `headers` only with `url`, e.g. `"Authorization": "Bearer ${TOKEN}"`, R-91), `disabled` keeps the server off, `trust` believes `readOnlyHint`, `tools` is the allowlist offered to the model (empty = all, R-88), `timeout_sec` 0..600 (`Timeout()` gives 60 s for 0). Names match `^[a-z0-9_-]{1,32}$` (they become `mcp__<name>__<tool>`).
- `Config{Provider, Providers, Prompt, Tools, Web, Session, Context, Tasks, Skills, MCP}` - whole file; `Provider` names the active entry.
- `LoadLayered(globalPath, explicit, projectDir) (Config, Layers, error)` (R-95, T10) - `Load` of the global file, then `.swarg/config.json` and `.swarg/config.local.json` of the project merged over it as JSON (objects key by key, lists and scalars replace; `deepMerge`), decoded once over `Defaults`; each project file is probed alone first so an unknown field names its file. `Layers{Project, ProjectServers, ProjectRaw, Warnings}`; `Layers.FromProject(key)`. The guard (R-96, I-33): `tools.auto_approve: true`, `web.confirm: false`, `mcp.confirm: false`, `mcp.servers.x.trust: true` from a project file are reset to the global values, one warning each.
- `Set(path, key, value, project bool) error` (R-98) - writes one dotted key into a JSON file (created when missing, other keys kept, indented, 0600); `project` refuses the unsafe values with `... is not allowed in a project file; use the global config`.
- `Approvals` (`approvals.go`, R-97, I-34): `LoadApprovals(dir)` reads `<dir>/approvals.json` (missing = empty); `Approved(project, server, MCPServer) bool`, `Approve(...)` saves; the value is a hash of the server entry, so a changed entry is unapproved again. Constants `ProjectDir`, `ProjectConfig`, `ProjectLocal`.
- `Dir() (string, error)` - `os.UserConfigDir()/swarg`.
- `Provider.Type` is `"openai"` (mlx_lm.server and other OpenAI-compatible servers), `"ollama"` (R-64) or `"openrouter"` (R-102); anything else fails validation. The type only changes `ThinkingBody()`: ollama -> `reasoning_effort: "high"`, temperature 0.6, top_p 0.95, presence_penalty 0; openrouter -> `{"reasoning": {"effort": "high"}}` only; openai -> the `chat_template_kwargs.enable_thinking` preset.
- `Defaults()` also holds the preset `providers.openrouter` (T11, R-102): type openrouter, `https://openrouter.ai/api/v1`, model `nvidia/nemotron-3.5-lightning:free`, 32768 context (the Catalog's `context_length` wins per model in cmd; the start provider's Catalog is fetched once on the first `limitFor`), 4096 max tokens, `api_key_env: OPENROUTER_API_KEY`, no `extra_body`.
- `(Provider) Validate(name) error` - the per-entry check (type, base_url, model, limits), split out of `Config.Validate`, which checks the ACTIVE entry only: an unused broken entry does not stop the start, `/server` shows it as `bad config`. `(Config) Ready(name) (Provider, error)` (R-100) - the entry can be switched to: defined, valid, and its `api_key_env` set when named (`provider "x": no key: set VAR`). `(Provider) Local() bool` (R-104) - plain http to localhost, a loopback/private/link-local literal IP or a plain host name is local; https or a public IP is a cloud service.
- `Recent` (`recent.go`, R-101): `LoadRecent(dir)` reads `<dir>/recent.json` (`{"models": {"<provider>": [ids newest first]}}`, missing = empty); `Models(provider)`, `First(provider, fallback)` (the model a switch starts with), `Use(provider, id)` (to the front, capped at 10, saved 0600).
- `Approvals` also keeps one-time notices (R-104): `Noticed(project, key) bool`, `Notice(project, key) error` (entry `notice:<key>`); a notice never counts as an MCP approval.
- `Defaults()` also holds the preset `providers.ollama` (type ollama, `http://127.0.0.1:11434/v1`, `qwen3.5:4b`, 16384 context, 4096 max tokens (a 250-line file is ~2800 tokens), `extra_body` = `reasoning_effort: "none"`, temperature 0.7, top_p 0.8, presence_penalty 1.5 - only keys Ollama reads from `/v1`). Use it with `{"provider":"ollama"}` plus `--base-url` / `SWARG_BASE_URL` for a server on another machine; a `providers.ollama` entry in the file replaces the preset as a whole.
- `Defaults() Config` - provider `local` (openai, `http://127.0.0.1:8080/v1`, `mlx-community/Qwen3.5-4B-4bit`, 16384 context, 2048 max tokens, `extra_body` with `enable_thinking` false and the Qwen3.5 non-thinking sampling: `temperature` 0.7, `top_p` 0.8, `top_k` 20, `min_p` 0, `presence_penalty` 1.5, `repetition_penalty` 1.0).
- `Load(path string, explicit bool) (Config, error)` - read, decode, validate.
- `(Config) Validate() error` - checks the active provider (including its `context_limits` values), `prompt.warn_share`, `tools.max_steps` (1..200), `tools.shell_timeout_sec` (1..3600), `session.keep` (>= 1), `context.auto_compact` (0 or 50..95) and the `tasks` ranges.
- `tools.background_grace_sec` (default 10, 0..600; 0 = background at once) and `tools.output_wait_sec` (default 10, 0..600; how long shell_output waits for a job end).
- `(Config) Active() Provider` - the active provider (zero value if undefined).
- `(*Config) Override(model, baseURL string)` - sets non-empty values on the active provider; call `Validate` afterwards.
  The cmd applies `opts.providerOverride()`: the `--model`/`--base-url` flags, else the `SWARG_MODEL`/`SWARG_BASE_URL` environment variables (flags win), so plain `swarg` inside the Docker sandbox reaches `http://model:8080/v1` without flags.
- `(Provider) APIKey() string` (R-105) - the env var named by `api_key_env`, else the Key of that name in the Keys file, else in the Old Key directory (`UserKeys().Lookup`); `""` otherwise. `(Provider) NoKey()` - the hint `no key: set VAR or add the line VAR=... to <keys.env> (chmod 600; /keys init creates it)`, used by `Ready`, `/server` and the start error.

- `KeyStore{File, OldDir}` (`keystore.go`, R-106, R-107, R-110, T12) - read-only view of the keys. `UserKeys()` = `<Dir()>/keys.env` and `<Dir()>/keys`. The file is parsed afresh on every call (`read`): `NAME=value` lines, `#` comments, blanks, optional BOM, one pair of quotes stripped, `NAME=` is no key; a file readable by group/others (Windows exempt) is ignored with a warning naming the file and `chmod 600`; a bad line gives `keys.env line N is not NAME=value and was skipped` (number only). `Lookup(name) (value, src)` (env, then file, then old dir; `src` is `SrcEnv` / `SrcFile` / `SrcOld`), `Expand(s)` (`$VAR` / `${VAR}` over the same order, file read once), `State(name)` / `States(names)` -> `KeyState{Env, File, Old, Value}`, `Names()` (names in the file and the old dir, sorted), `Warnings()`, `OldHint()` (one-line hint when old key files exist; nothing is moved or deleted), `Init(names)` (commented 0600 template with a `# NAME=` line per valid name; `O_EXCL`, so `ErrKeysFileExists` and the file untouched when it exists; MkdirAll 0700 for the config dir). There is no Set or Delete: swarg never writes a key value. `MaskKey(v)` - first 6 + `…` + last 4 for 16+ characters, else `set`. `KeyUsers(cfg) map[name][]who` - providers' `api_key_env` and `$VAR` in MCP `headers` / `env` (`provider x`, `mcp s header H`, `mcp s env E`).

Invariants:
- Missing file: `Defaults()` when not explicit; error naming the path when explicit.
- Unknown fields and trailing data after the JSON value are errors.
- A provider entry in the file replaces the default entry of the same name as a whole (no field merge).
- A `tools` object in the file is decoded onto the defaults: missing keys keep their defaults; a file without `tools` keeps all of them.
- Validation errors start with `config: `.

Gotchas:
- `Validate` checks only the active provider, not the other entries.
- `Override` does nothing when the active provider is missing; `Validate` then reports it.
- `APIKey` never reads the key from config.json; only the env var name is stored there. Keys live in `<config dir>/keys.env` (edited by the user; only `KeyStore.Init` creates the template). Tests use `KeyStore{File, OldDir}` over `t.TempDir()` or point HOME/XDG_CONFIG_HOME/AppData at a temp dir (`isolateUserKeys`), else a real key file on the dev machine would leak into "no key" tests. Warnings carry file names and line numbers only, never a value.
- A user `extra_body` replaces the whole default map, sampling keys included; set them again in the file if they are still wanted.
- Ollama: without `reasoning_effort` in `extra_body` Qwen3.5 thinks by default (the preset sends `"none"`). The context window is the server's `OLLAMA_CONTEXT_LENGTH` (default 4096), not settable through `/v1`; keep `context_limit` equal to it, or the agent warns about a truncated prompt (R-65).
- The built-in context table (`defaultLimits`) beats an explicit `context_limit` for its model ids: `context_limit: 4096` with model `mlx-community/Qwen3.5-4B-4bit` still gives 32768. To use less for such a model, set `context_limits` for that id in the file.
- The table is deliberately NOT in `Defaults()`: a file that defines `providers.local` replaces the whole entry, which would silently drop a table stored there. `LimitFor` reads it from the package var, so it survives such a file.

## cmd/swarg (main, flags, wiring)

T8 S/M wiring (`main.go`, `tools.go`, `views.go`, `extra.go`): `skills.Load(<config dir>/skills, cwd, cfg.Skills.Disabled)`; with at least one Skill the `skill` Tool joins the tool set and the `skills` prompt block (Order 1500) is added; `mcp.New(cfg.MCP.Servers, ...)` + `Start` (warnings to stderr, `Close` deferred) only when servers are configured, with the `mcp` block (Order 1600, the servers' instructions). `toolRunner` routes `mcp__*` names to the client (Specs = Set + MCP on every request). `extraPromptWarning(sk, mc)` prints one stderr line when the Skill list + skill Tool + MCP specs + mcp block exceed `extraPromptCeiling` (1500 tokens, R-89), naming the three biggest items; nothing is dropped. `skillsView` / `mcpView` adapt both for the UI and rewrite the run-time blocks (`prompt.Set.SetText`) on `/skills on|off`, `/mcp on|off|restart`.

Prompt profiles (`profiles.go`, T13 B, R-116..R-118): `profiles{set, cfg, sc, record, current}` implements `ui.PromptAPI` and applies the Profile to the prompt Set. `Restore(saved, model)` at start and on a `/resume` switch (`saving.onProfile`): a recorded name (valid) is an explicit choice, else the config decides (`ProfileFor(active Source, model)`; an unknown name falls back to compact). `OnEvent` (wrapped around `onModel` in `OnEvent`) re-resolves on every `EvModel` while the choice is not explicit. `Choose(name, scope)` applies, marks explicit, records through `saving.RecordProfile` (the SessionFile `prompt` line) and with a scope writes `prompt.profile` (a failed write is a `ui.NotSavedError`; the choice stays). The `/config` row `prompt profile` (Live `profile`) comes from `configView.profile`.

Files: `main.go` (run, wiring), `flags.go` (`parseArgs`), `sessions.go` (session picking, `saving` = the files being written + `ui.SessionsAPI`, `cleanups`), `tracecmd.go` (`swarg trace`), `jobs.go` (jobs adapter, `killOnSignal`), `tools.go`.

Flags: `--config`, `--model`, `--base-url`, `--yes`, `--version`, plus
- `--continue` resume the newest readable session of this project (none: notice, new session);
- `-c` short for `--continue`;
- `--resume <id>` / `-r <id>` / `--resume=<id>` resume that session; an id prefix is enough; ambiguous or unknown id is an error (exit 1) listing the candidates; not combinable with `--continue`;
- `-r` / `--resume` WITHOUT an id (last arg, or followed by a `-flag`; `scanPick` pre-scans because Go's flag package has no optional values) = pick mode: on a terminal the `ui.PickSession` full-screen picker lists this folder's sessions (cancel: exit 0, nothing starts; chosen id then continues like `--resume <id>`); no sessions: `no saved sessions in this folder`, exit 0; without a terminal the list goes to stdout, hint `use swarg -r <id>` to stderr, exit 2 (`choosePick`);
- `--sessions` print `id  started  model  messages  title` of this project, newest first, exit 0;
- `--no-save` no SessionFile (and no Trace); `--trace-off` no Trace.
Subcommand `swarg trace [id]` (os.Args[1] == "trace", before flag parsing): prints `trace.Timeline` of the session (id prefix) or the newest of this project; no trace file is exit 1; extra arguments are exit 2.
Exit codes: 0 ok, 1 runtime error (also unknown session id), 2 config or flag error.

`Config.Cost{WarnUSD}` (`cost.warn_usd`, T13, R-114): USD, 0 = off (default); validation refuses a negative value, NaN or more than 1e6. Main passes it as `agent.Deps.WarnUSD`. File only: there is no `/config` row (the menu has no float kind). A project file may set it (it only warns).

Thinking (R-60): `Provider.Thinking` (default false) is the start mode of a NEW session; a resumed one uses `session.Loaded.Thinking()` (absent = off, I-30), passed as `agent.WithThinking`. `Provider.ThinkingBody()` (built-in Qwen preset, laid over `ExtraBody` by the agent as `Deps.ThinkExtra`; nested `chat_template_kwargs` merged) and `ThinkingLimit()` (`thinking_max_tokens`, 0 = 8192, negative is invalid; `Deps.ThinkTokens`; a larger `max_tokens` is kept); a resumed session without a think line starts off even if the config says `thinking: true`. `swStore.Thinking` forwards to the writer of the moment. Old configs without the fields behave as before.
Idle timeout (R-63): `Provider.IdleTimeoutSec` (`idle_timeout_s`, 0 = 600 s) via `IdleTimeout()`; main sets `openai.Client.IdleTimeout` from it. Long because mlx_lm.server sends a tool call in one chunk at the end of the generation.

Model at start (`startModel`, R-30): `--model` > the resumed session's last model (`session.Loaded.Model`) > config/`SWARG_MODEL`. The agent starts with the session's own model and main then calls `SetModel(model)`, so a `--model` over a resumed session is recorded. `onModel` wraps `OnEvent`: an `EvModel` first rewrites the prompt env block (`prompt.Set.SetModel`) and records the model in the active Source's Recent list. `Health` checks `a.Model()`.

Sources (`sources.go`, T11, R-100..R-104): `sources` adapts the config's providers to `ui.ServersAPI` and `ui.ModelsAPI`: one `openai.Client` per provider made on first use (`client(name)`, idle timeout from the entry), the active name, the Catalog per probed or listed provider. `Switch(name)`: `cfg.Ready`, the active name is set BEFORE `Agent.SetSource` (its `EvModel` must be recorded under the new Source; found by the live look), an openrouter Source fetches its Catalog first (best effort), the model is `recent.First(name, entry.Model)`, `LimitFor` = the Catalog's `context_length` else the entry's `LimitFor`; the cloud notice (`Approvals.Notice(cwd, "cloud")`) is returned once per project for a non-`Local()` entry. `Servers(ctx)`: rows sorted by name, states `ok` / `down: <net cause without the URL>` / `no key: set VAR` / `bad config: <reason>`, probed in parallel with `Catalog` (5 s each). `List(ctx)`: the active Catalog, tool-capable only when `supported_parameters` is reported, Recent marked, `Price` = `free` or `$in/$out per M`. Start: the resumed session's provider (`session.Loaded.Provider`) replaces the configured one when it exists (hint `continuing on the session's source X`; the command-line overrides are re-applied to it); the active provider with an empty `api_key_env` is exit 2 `provider "x": no key: set VAR`; the SessionFile header records the provider; `agent.Deps.Source` is the name.

Wiring: project session dir = `session.Dir(config.Dir(), cwd)`. Unless `--no-save` / `session.save: false`: `session.Prune(dir, keep)`, then `session.Create` (or `session.Open` of the resumed file, whose history goes in through `agent.Load(..., WithMaxSeq)` and `ui.Deps.History`) -> `agent.Deps.Store`; Trace via `trace.Open(session.TracePath)` unless `--trace-off` / `session.trace: false` -> `agent.Deps.Trace`. Plain mode saves too. A problem creating the files is a stderr warning and the run goes on unsaved. Files are closed by `cleanups` on every exit path including SIGHUP/SIGTERM (`killOnSignal`); a new session that got no message is deleted again. After the UI ends, `session saved: swarg --continue` goes to stderr when the session has at least one message.

`saving` (T3 ui, R-33): the `*session.Writer` and `*trace.Writer` of the moment behind one mutex; the agent's Store (`swStore`) and Trace (`swTrace`) forward every call to them. It is `ui.Deps.Sessions` (`ui.SessionsAPI`): `List` (readable sessions with Messages), `Current` (id of the file being written), `Open(id)` (an id prefix is enough: closes the current files - a new file without a message is removed -, reopens the chosen SessionFile and its Trace with `session.Open` / `trace.Open`, returns `ui.Opened{History, MaxSeq, Model, Title}`; opening the current session or any session while saving is off only returns the history; a file that cannot be opened for writing leaves the current one in place), `Delete(id)` (`session.Delete`; the current session is refused, R-34), `Rename(name)` (`Writer.Name`; "sessions are not saved" without a writer). A model change should be recorded through the writer of the moment (`saving.w` under `saving.mu`), never through one captured at start.

Gotchas:
- Opening a session in the UI SWITCHES the file: what happens next is appended to the opened SessionFile (a true continuation). `session saved: swarg --continue` still names `--continue`, which resumes the NEWEST file by start time - after a switch to an older session use `swarg -r <id>` (the picker shows it).
- A new file that got no message is removed on exit or switch, unless it was renamed: a Name counts as content (`Rename` clears `fresh`).
- Resuming appends to the same SessionFile and Trace (the Trace `ms` counter restarts at 0; also after every switch).
- `agent.Deps.AutoCompact` is not wired yet (`TODO(W2.1b)` in `main.go`).

- The `openrouter` preset has `profile: "standard"` (R-129); local presets have none, so they stay `compact` (R-116).
