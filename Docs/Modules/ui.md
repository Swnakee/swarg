# Module ui (`App/internal/ui`)

Purpose: the terminal front end. `Run` is the FULL-SCREEN Bubble Tea UI (alt screen, mouse always on; T2_4). The inline mode is gone. `RunPlain` (`plain.go`) is the pipe mode and is unchanged. The UI talks to the core only through `AgentAPI` / `BlockAPI` (`api.go`).

API:
- `Run(ctx, d Deps) error` - create the program, start the agent after it exists, block until quit.
- `ParseCommand(line) (Command, error)` - driven by the `commands` table (`commands.go`: `cmdSpec{name, args, desc, kind, parse}`, display order = `/help` order): `/help /clear /compact /task <goal> /sessions /resume /rename <name> /context /tool N /bg /auto /blocks /block on|off <name> /model [id|N] /server [name] /think [on|off] /skill <name> [text] /skills [on|off <name>] /mcp [<server> | on|off|restart <server>] /exit`; plain text and `//x` give `KindText`; unknown `/x` is `unknown command /x (see /help)`; a command without `parse` takes no arguments (`usage: /x`). `helpText()` is the `/help` notice. Adding a command = one table entry + one `case` in `model.submit` (core adds `/model` this way).
- `NewInbox() (send, events)` - unbounded event queue; `send` -> `agent.Deps.OnEvent`, `events` -> `Deps.Events`.
- `NewApprover(yes) *Approver`; `Approve(ctx, call) agent.Approval` -> `agent.Deps.Approve`; `Bind(send)` (called by `Run`); `SetAuto/Auto`. Unbound (plain mode): allow if `yes`, else deny with "not approved: run with --yes to allow".
- `ToolLine(n, name, label, brief, err) (head, tail)` - the collapsed `● name(label)  #N` / `  └ brief` lines (`└ ✘ error: ...`), shared with plain mode. `Clean(s)` strips control chars (apply to all model/file text).
- `Deps{Agent, Blocks, Events, Approver, Jobs, Sessions, History, SavedHint, Model, Project, Limit, Yes, AutoApprove}`; `AgentAPI` includes `Abort()` and `Background() bool`. `JobsAPI{List() []JobRow}`, `JobRow{ID, Command string; Running bool; ExitCode int}` - main adapts `tools.Jobs`; `ui` does not import `tools`. `Deps.Jobs` and `Deps.Sessions` may be nil.
- Sessions (`api.go`, T3 ui): `SessionRow{ID, Title, Model string; Time time.Time; Messages int}` (Title = the Name, else the first user message), `Opened{History, MaxSeq, Model, Think, Title}`, `SessionsAPI{List() ([]SessionRow, error); Open(id) (Opened, error); Delete(id) error; Rename(name) error; Current() string}` (`Deps.Sessions`, nil = "sessions are not saved"). `Open` SWITCHES the SessionFile being written (main's `saving`), `Current` is its id. Optional agent parts used through a type assertion on `Deps.Agent`: `compacter{Compact(ctx) error}` and `loader{Load([]chat.Message, ...agent.LoadOption) error}` (called as `Load(o.History, agent.WithMaxSeq(o.MaxSeq))`).
- `Deps.History` (optional): the list is pre-filled from it in `newModel` exactly like `/resume` does (no "resumed" notice; main may add one). `Deps.SavedHint` (optional): the UI never prints it; `Run` returns and main prints it (e.g. `session saved: swarg --continue`).
- Session commands (`cmds_session.go`, T3 ui): `/compact` -> `Compact(ctx)`; when a Turn or Compaction runs or `Agent.Busy()` the notice `compaction queued` is added (the agent queues it). `/sessions` and `/resume` (the same) -> `openPicker`: the saved Sessions (newest first by `Time`; the UI sorts, `List` order is not trusted) in the embedded picker (`model.pick`, see Session picker below). Opening (`openSession`, R-33): idle only (`wait for the turn to end`), `Sessions.Open(id)` -> `Agent.Load(o.History, WithMaxSeq(o.MaxSeq))` -> `rebuild` -> notice `resumed session <title>` and the picker closes; a failure keeps the picker open with the reason in its footer (`model.note`: footer while the picker is open, else a list notice). `/rename <name>` -> `Sessions.Rename` -> `session renamed to <name>` (R-32). `/help` -> `helpText()`. `/context` -> notice from the last `EvMeter` (`Breakdown` per category with %, total meter, `cache N%`); `no context data yet` before the first meter.
- `rebuild(history)` resets list, records, numbering and scroll, then adds: user items, assistant items (`Summary` -> dim notice `work summary` + text), tool items from assistant `ToolCalls` joined with their `RoleTool` result by `ToolCallID` (label = `Message.Label`, brief = `Brief`, `Failed` -> error, output = `Content`); a call without a result shows `cancelled: turn ended`. `/tool N` and Ctrl+O work on loaded blocks.
- Compaction (`compact_events.go`, the only file naming `agent.EvCompactStarted/EvCompacted`): `EvCompactStarted` sets `model.compacting` (status `compacting…` + a spinner row, timer started, `working()` = busy or compacting: Esc sends Interrupt/Abort, quit waits); `EvCompacted` adds the notice `compacted N spans: ~B → ~A tokens`, completes a pending quit. `EvTurnStarted` clears the flag (safety). Plain mode prints `[compacting…]` / `[compacted N spans: ~B → ~A tokens]` via `compactLine`; warnings are shown as before.
- Keys: ctrl+o (toggle the last tool block, scroll to it only if its head is off screen), ctrl+b (`Agent.Background()`), esc (1st Interrupt, later Abort, per Turn; idle = nothing), PgUp/PgDn (scroll the list a page minus one row, always), Home/End (scroll to top/bottom when the input is empty, else the textarea's), ctrl+Home/ctrl+End (always scroll), wheel (3 rows), Esc first clears a selection if one exists (no interrupt). Mouse: see Mouse below.
- Glyphs live in one const block in `tools_view.go` (`glyph*`, `glyphFrames`).
- `model` (unexported, `ui.go`) - Bubble Tea model. Files: `view.go` (screen), `scroll.go` (viewport), `keys.go`, `commands.go`, `live.go` (tool output rules, kept output, block rows), `tools_view.go` (call records, `/tool`, Ctrl+O), `bg.go` (jobs, ctrl+b), `conv*.go` + `wrap.go` (the list, below).
- Every colour comes from `mdstream.Colors` (`TestNoColourLiteralsOutsideTheme`).

Screen (`view.go`):
- Frame = exactly `height` rows (24 until the first `WindowSizeMsg`), every row `StringWidth <= width`. From the top: the content (list rows, then the FOOTER right under the last item, then empty rows), the pinned ask prompt (only while a confirmation waits), the input box (rounded border, 1-6 text lines), the Bottom panel. List height = height - ask rows - box - panel; the ask rows give way first so the list keeps at least one row; an ask prompt taller than its room keeps the first rows and the `[y]es / [n]o / [a]lways` line. The box stays under the ask prompt (the user types a note there) and the list keeps updating above.
- Footer (`footer()`, R-27, R-28): the Waiting Messages (`waiting.go`: dim `▸ text  (waiting)`, wrapped, oldest first), then the Progress line (`progressLine()`: spinner, `Thinking…`/tool work, time, `reading prompt N/M`, `↓ ~N tokens` (every streamed chunk incl. reasoning and tool arguments, R-61), live `~N tok/s`, `esc to stop`; `Stopping…`; `compacting…`; the quit hint) while `working()` or quitting and no ask prompt is shown. Footer rows are content, not list items: `contentTotal()` = list rows + footer rows sets `maxOffset`; following shows the last list rows then the whole footer; not following, the footer appears only when the window reaches past the last item; `rowAt` is false there (no click, selection or hover).
- Below 20 columns or 5 rows the frame is `terminal too small` padded to `height` rows. The textarea `MaxHeight` follows the height (`max(h-4,1)` capped at 6).
- `View()` sets `AltScreen`, `MouseModeCellMotion` always, and the real cursor at absolute coordinates inside the box (`boxTop+1+ta.Y`, `ta.X+1`). `KeyboardEnhancements` stays zero (Bubble Tea always requests key disambiguation, which is what makes shift+enter arrive).
- Bottom panel (`panel.go`, R-31): `provider/model │ meter │ N tok/s │ ◉ auto|○ ask │ ⧗ N bg │ copied N lines` (jobs only when > 0, the copy note while set). The provider part (`model.providerName`, from `Deps.Provider`, then every `EvProvider`; absent when "") is its own hotspot `panel:server` glued to the model item (`panelItem.glue`: no separator) and opens `/server`. The model label is `model.modelName` (from `Deps.Model`, then every `EvModel`); the speed is the last `EvSpeed` (`– tok/s` before any; one decimal below 10). The model and jobs items register hover spots `panel:model` / `panel:jobs` in `screen()` (`hotPanel`); a press+release on the same cell (`press.panel`, found with `hv.at`) runs `/model` or `/bg`. Project, cache share (in `/context`), compacting (Progress line) and the queue count (Waiting Messages) are not on the panel.
- Waiting Messages (`waiting.go`, R-27, I-8): `submit` of a text adds it to `model.waiting` before `Agent.Submit`; `EvTurnStarted` and `EvUserText` drop the first equal waiting text (`takeWaiting`) and add the user item as before. Commands never wait. The bug it fixes: a text sent during a long text-only answer was invisible until the Turn ended.
- Task blocks (`task_view.go`, `conv_render.go`, R-62): `EvTaskStarted` opens the Task's block, `EvTaskEnded` folds it; every row of an item with `depth > 0` is painted with `mdstream.Colors.TaskBg` plus the fixed text colour `UserFg` across the width (`withTaskBackground` re-applies both after each reset, long or short form; a painted cell never keeps the terminal's own foreground, see `readable_test.go`; copying strips the background with the other backgrounds).
- Live speed (`panel.go`): every `EvDelta` and `EvActivity` (reasoning, tool arguments) counts one chunk (`liveN`, ~1 token with mlx); after 0.5 s of streaming the Progress line and the panel show `~N tok/s` = (chunks-1) / time since the first chunk (`model.now`, the tick clock). Reset at `EvTurnStarted`, `EvToolStart`, `EvSpeed`.
- `/think [on|off]` (`models.go`, R-60): optional agent part `thinker{SetThinking(bool)}`; no argument shows `thinking: on|off`; `Deps.Think`/`EvThinking` feed `model.thinking`; the panel shows a `think` item (not clickable) only while on. `/resume` and the picker pass `agent.WithThinking(o.Think)`.
- `/skill <name> [text]`, `/skills`, `/mcp` (`skills_mcp.go`, T8 S/M): `/skill` goes through the optional agent part `skillSubmitter{SubmitSkill}` (notice `no skills loaded (see /skills)` on `agent.ErrNoSkills`) and adds the text (or `agent.SkillOnlyText`) as a Waiting Message; an unknown `/<name>` whose name is a loaded Skill (`Deps.Skills.List`) is the same as `/skill <name>` (`skillLine`; a built-in command of that name wins because `ParseCommand` runs first). `/skills` lists `◉ name  source  description` / `○ ... (off)` from `Deps.Skills` (`SkillsAPI{List, SetEnabled}`, rows `SkillRow`); `/skills on|off <name>` toggles for this run. `/mcp` lists `name  state  N tools  reason` from `Deps.MCP` (`MCPAPI{Servers, Tools, SetEnabled, Restart}`, rows `MCPServerRow`, `MCPToolRow`; a running but switched-off server shows `hidden`); `/mcp <server>` lists its tools with `[read-only]` / `(not offered)` and the stderr tail; `/mcp on|off|restart <server>`. `/mcp on` alone is a usage error (no server may be named on/off/restart). Nil `Deps.Skills` / `Deps.MCP` give a notice saying how to set them up. Main adapts both (`cmd/swarg/views.go`); `ui` imports neither `skills` nor `mcp`.
- `/server [name]` (`servers.go`, T11, R-100): `Deps.Servers ServersAPI{Servers(ctx) ([]ServerRow, error); Switch(name) (notice, err)}`, `ServerRow{Name, Type, Address, State; Active}`. Without a name the rows are fetched in a command (`serversMsg`) and shown as a menu `name  type  address  state` (active marked; Enter switches); with a name `Switch` runs at once. The notice is `server: <name> (used from the next request)` plus the adapter's cloud notice when returned; errors are notices (`server: <err>`); nil `Deps.Servers` says the sources are not available.
- `/model` rows (T11, R-101, R-102): `ModelsAPI.List` returns `[]ModelRow{ID, Name, Price; Recent}`; the menu puts Recent rows first (stable), shows `id  name` with `Price` as the right label, `Match` = id + name (typing searches both); `model.modelRows` keeps the shown order for `/model N`.
- `/model` (`models.go`, R-30): `/model <id>` sets it through the optional agent part `modelSetter{SetModel}` (notice `model: <id> (used from the next request)`); `/model N` picks from the last shown list; `/model` alone fetches `Deps.Models.List` in a command (`modelsMsg`) and shows a numbered notice list, the model in use marked `◉`. Errors (no list source, server error, empty list, refusal, agent without SetModel) are notices.

Scrolling (`scroll.go`):
- `scrollState{follow, aItem, aRow, base}`. While `follow` the list shows its last rows (`conv.tailRows`, cheap) and stays there as rows arrive. Otherwise the viewport top is the ANCHOR (item, row inside the item), so rows added or re-wrapped elsewhere do not move what is read, and a resize keeps the same item on top. Reaching the bottom (wheel, PgDn, End, a shrunk list via `settle()` after every Update) follows again.
- `base` = list height when following stopped; while not following the last list row shows `↓ N new rows` once N > 0.
- `scrollTo(y)` is the one entry (clamps, sets follow/anchor); `/tool N` and Ctrl+O use it. `viewTop`, `listHeight`, `rowVisible` are the readers.

Events -> list (`ui.go`, `tools_view.go`, `live.go`):
- `EvTurnStarted`/`EvUserText` add a user item; `EvDelta` feeds the streaming assistant item (`model.cur`, created by the first delta; raw text goes in - the list cleans whole text so a chunk split inside a rune or an escape is safe); `say(text)`, tool start and user text end the streaming item first, so order follows event order; the next delta starts a new item.
- Interrupt: `EvTurnEnded` with `FinishInterrupted` finalises the live item IN PLACE (`endAssistant(i, true)`: open fence closed, ONE dim `interrupted` row inside the item); only when no live item exists (interrupt during a tool, or before any text) a notice `interrupted` is added. Running calls end as `cancelled: turn ended`.
- Tool calls: `EvToolStart` adds a tool item (`callRec.item` = list index) and a record in `m.calls` (numbered `#N`, per session, reset by `/clear`, capped at `maxCalls` = 2000 records; the LIST keeps every block, `/tool N` of a dropped record says `no tool call #N`). `m.runN` = numbers of running calls. `EvToolOutput` appends to a per-call byte buffer (`m.outBuf`, trimmed at 2x the cap: no quadratic copies); `syncOutputs()` publishes buffers to the records and the list ONCE per event batch. Kept output per block: 256 KB (`maxLiveOutput`, tail kept, cut at a rune start), also applied to the final `EvToolEnd` output.
- `/clear`: `Agent.Clear()`, only on nil error the list, records, numbering and scroll reset; no escape sequences, no notice.
- Quit while busy: `Interrupt`, hint shown, quit on `EvTurnEnded` (after the drain); a second ctrl+c quits at once.
- Events arrive via `Deps.Events`; `readEvents` blocks for one event and drains the rest, so deltas coalesce; it is re-issued only after the batch was handled. `Update` returns `tea.Batch(reader, m.side...)`.

Tool rows (in the list; `blockRowsAt` in `live.go`, used by `conv_render.go`):
- Head `● name(label)  #N` (plus a spinner glyph while running); running closed = last 5 output lines; done closed = head + result line, and for a successful `shell` call a preview under it: the FIRST 3 output lines with the `  │ ` prefix, then `  … +N lines (/tool N)`. The trailing status line (`[exit N]`, `[killed: why]`) and trailing blank lines are dropped from the preview. OPEN (done or running) = ALL kept output lines, wrapped, no 15-line cap and no "more lines" row. Output lines pass `outputLines`: CRLF, `\r` progress (last state wins), `Clean`, tabs to 4 spaces. Every row is wrapped (not cut) to the width, continuation rows keep the `  │ ` prefix.
- Confirmation: `Approver.Approve` sends `askMsg` into the program and blocks on a buffered reply or `ctx.Done()`. y/n/a act only with an empty input and 300 ms after the prompt (model clock); within those 300 ms they are DROPPED, not typed (a typed-ahead `y` in the input left the prompt waiting while every further `y` joined the input: 885 of them in agent-1's harness); other keys start a note. While the input is not empty the prompt ends with the hint `clear the input (Ctrl+U) to answer y/n/a; Enter sends the text and denies`. Enter with text calls `Submit` first, then denies with the text as note; Esc denies and interrupts. The prompt shows the full command / edit preview (5 lines) / write size; `shell` with `background:true` shows `(background)`; `shell_kill` shows `bgN: <command>`.
- Ctrl+B: `Agent.Background()`; when it returns false and no call runs, the key is not handled (textarea cursor-left); with a non-detachable call running it adds a notice. Ignored during an ask. tmux eats Ctrl+B (its prefix).
- Status `⧗ N bg`: `refreshJobs` runs at `EvToolEnd`, `/bg` and on `bgTickMsg`; a 1 s tick (`m.bgTick`, a field so tests need no timer) is kept alive only while a job runs, also when idle.

Gotchas:
- Tests drive `Update` directly and walk the returned cmd tree with reflect (`tea.Batch` is a slice of Cmd); `model.tick`/`bgTick` are fields so tests start no timer. Rig: `rig.rows()` (screen rows), `rig.convText()` (all list text, ignoring scroll), `rig.wantLine(res, part)` looks into `convText()`, `wantFrame(t, r, w, h)` asserts the frame invariants (exactly h rows, widths, intact box borders), `rig.open(n)` expands block n.
- Textarea: `MaxHeight` is the visible rows (<= 6); `MaxContentHeight` lifts the content limit (otherwise typing stops at 6 logical lines).
- The empty-answer notice comes from the agent as `EvWarning`; the UI adds none of its own.
- `ansi.Hardwrap` is used for long words; a width below ~5 gives rows wider than the width for the output prefix, hence the 20-column minimum.
- Not done by the UI: the `session saved: swarg --continue` line on exit (main prints `Deps.SavedHint`).

Conversation list `conv` (T2_4 W1.3a, wired into the model in W1.3b; files `conv.go`, `conv_render.go`, `wrap.go`):
- `conv` is Bubble-Tea-free: `newConv()`, `setWidth(w)` (a change drops every cache), `setFrame(f)` (spinner; only running tools depend on it), `reset()`.
- Items (`convItem`, kinds `itemUser|itemAssistant|itemNotice|itemTool`): `addUser(text) int`, `addNotice(text) int`, `addTool(callRec) int` (the list keeps its own copy of the record), `addAssistant() int` (live). All return the item index.
- Changes: `feed(i, delta)` (live assistant; delta must already be `Clean`; goes through an `mdstream.Committer`), `endAssistant(i, interrupted)` (renders once as a whole from the raw text; interrupted: an open fence is closed in the raw text and a dim `interrupted` row is added), `setTool(i, rec)` (replace the record, bumps the version), `setOpen(i, open)`, `toggle(i) bool`.
- Reading: `count()`, `at(i) *convItem`, `height(i)`, `total()`, `top(i)` (first row of item i), `rows(offset, h)` (window, clipped), `tailRows(h) (rows, first, firstRow)` (last h rows touching only the tail items; the follow-tail view), `rowAt(y) (idx, row, head, ok)` (head = a head row of a tool block, the row a click toggles; a wrapped head has several).
- Cache per item keyed by (width, open, version, frame-if-running-tool). Only `feed`, `endAssistant`, `setTool` bump the version; `setOpen` changes the key. Heights are exact and measured lazily through prefix sums (`pre`): `rows` measures only the items up to the end of the window, `total`/`top` measure what they need once per width; a change at item k forgets the sums from k on, so appends cost one render each. `c.renders` counts item renders (tests).
- Live assistant item: committed blocks are rendered once per width (kept between versions), the open tail is re-rendered per delta. At the end the whole raw text is rendered by one `renderMarkdown` call (a package var = `mdstream.Render`, swapped by tests) and the live rows are replaced.
- Wrapping (`wrap.go`): every row is `ansi.StringWidth <= width`: `wrapRow` (hard wrap, wide runes and ANSI aware; a cut styled row ends with a reset, the style is not re-opened on the continuation), `wrapText` (word wrap + hard wrap, tabs to 4 spaces, empty line = one row), `splitRows`. Markdown output is wrapped after Glamour (long words, code, tables).
- Tool items use `blockRowsAt(r, open, vis, lines, width, frame)` from `live.go`: output lines wrap with the `  │ ` prefix repeated on continuation rows; an open item passes vis = all kept output lines (no 15-line cap, no "more lines" note). Closed items keep the old rules (5 running lines, 3-line shell preview).
- Gotchas: `Clean` is applied at render time on whole text, so a chunk that splits a UTF-8 rune is safe in `feed` (the model passes raw deltas); zero-height items (an assistant that ended without text) are skipped by `rowAt`.

Mouse, selection, copy (T2_4 W2.2; `mouse.go`, `select.go`):
- Click = `MouseClickMsg` (left) + `MouseReleaseMsg` on the same cell, no motion to another cell. If the pressed row is a head row of a tool block (`conv.rowAt` head) the block toggles (any block of the session, also during an ask; a click never answers the ask). Scroll anchor rules are those of `scroll.go`: not following keeps the top (item,row), following stays at the bottom. Press/release outside the list rows (input box, status, empty space below the content, the `↓ N new rows` marker row) does nothing. Only the left button acts. A press always clears the previous selection and the `copied` note.
- Drag = `MouseMotionMsg` (left held) to a cell other than the press cell. A drag never toggles. The selection is `selection{a,b selPoint}`, `selPoint{item,row,col}` = content coordinates, so it survives scrolling and changes of other items. Motion at list row 0 scrolls up 1 row, at the last list row (or below) scrolls down 1 row, per event. A release on another cell with no motion event counts as a drag.
- Selection is cleared by: a press, Esc (before its interrupt meaning, only when one exists), a `WindowSizeMsg` that changes the size, `/clear`.
- Highlight: `model.highlight` in `listRows` puts cells in plain reverse video (`reverseSpan`): the selected cells lose their own colours (reverse of a coloured cell put dark text on the dark terminal), `ansi.Cut` restores the style after the span. Trailing padding (user rows) is not highlighted. Cell columns are mapped to graphemes with `uniseg` (`cellSpan`): a wide char half inside the range counts whole. `go.mod` lists `github.com/rivo/uniseg` as a direct dependency for this.
- Copy on release after a drag: `selectionText` strips ANSI, drops the gutters `  │ ` / `  └ ` of tool blocks (the `● ` head glyph stays), trims trailing spaces per row, joins rows with `\n` except soft-wrapped continuation rows: a cut inside a word or at a cell boundary joins directly, a cut at a space joins with one space. Sent with `tea.SetClipboard` (OSC 52); the status line shows `copied N lines` (`model.copyNote`, not a list item). An all-blank selection copies nothing and is dropped.
- Soft-wrap flags: the `*S` wrappers in `wrap.go` (`wrapRowS`, `wrapTextS`, `splitRowsS`) put a zero-width APC mark (`markHard`/`markWord`) at the start of each continuation row; `conv.itemRows` strips the marks into `itemCache.cont` (`contNone|contHard|contWord`) so no mark ever reaches the screen. The unmarked `wrapRow/wrapText/splitRows` (ask prompt) are unchanged. Marks survive lipgloss styling because they are ESC sequences; `Clean` removes ESC from content so they cannot collide. Markdown rows come from `mdstream.RenderSoft`, which adds `MarkSoft` (= `markWord`) to rows glamour wrapped inside a paragraph/list item/heading and a lead mark (`mdstream.Lead(n)`) with the cells of renderer margin; `splitMarks` strips both into `itemCache.cont` and `itemCache.lead`, and `rowText` drops `lead` cells from the copy. So a copied answer has no 2-space margin, glamour wraps join with one space, paragraphs/list items/headings/table rows keep their line breaks, code rows keep only their own indentation and never join.
- Start: `model.Init` and `picker.Init` return `tea.ClearScreen` (with the alt screen it makes the renderer erase the whole terminal on the first frame, so rows of an earlier program cannot show through empty rows; empty rows are cells the renderer never writes, padding them with spaces would not change that).
- Not done: double-click word selection (optional in the plan), keyboard selection, focusing the input box by click.
- Gotchas: a one-cell selection cannot be made by a drag (a release on the press cell is a click). Hard-wrapped rows lose trailing spaces at the cut when copied (padding of user rows cannot be told from real spaces). Rig helpers: `rig.press/move/release/click/drag`, `result.clip` (the `SetClipboard` text).

## Command suggestions and highlight (`suggest.go`, T3 ui item 6, R-35)

- `suggestions(line)`: the `commands` whose name starts with the input while it is one `/token` (no blank, not `//`), table order (`bottom()` cuts the rows to the room above the box, so a short screen shows fewer); `isCommandLine(line)`: a `/token` with matches or a known command followed by arguments.
- Rows show in the extra area of `bottom()` (above the input box; an ask prompt wins, the spinner gives way): `  /rename <name>  name this session`, the selected one (`model.suggSel`, clamped by `current()`) in `pickSel`; each row is a hotspot `cmd:<i>` (`bottomArea.hot`, y relative to the first extra row; `screen()` registers them at `listH+y`), so hover underlines it and a click completes it (`mouse.go` `clickSpot`, the dispatch point for spots outside the list). Keys while suggesting (`keys.go`, after the picker and the ask): Tab completes the selected (`completeSuggestion`: the name, plus a trailing space when the command takes arguments, cursor at the end), Up/Down move with wrap; Enter submits the line as typed (an unknown `/re` says `unknown command /re (see /help)`). The picker and a confirmation hide the suggestions (`suggesting()`).
- Highlight: `styleInput()` after every textarea update resets the selection when the text changed (`model.typed`) and sets `Focused.Text` AND `Focused.CursorLine` to `cmdStyle` (Accent) while `isCommandLine`, else the default; the cursor line has its own style in the textarea, so setting `Text` alone would not colour a one-line input.
- Gotcha: the extra area is cut to the room above the box (`bottom()`), and `bottomArea.hot` is cut with it, so a spot never points at a row that is not shown.

## Hover (`hover.go`, T3 ui item 2, R-36, I-10)

- `hover` (`model.hv`, `picker.hv`): the pointer cell (`x, y, on`) and the hotspots registered during the last draw. `move(x, y)` on every `MouseMotionMsg` whose `Button` is `MouseNone` (and on a press); `begin()` at the start of a draw forgets the spots; `add(id, y, x0, x1) bool` registers a clickable span of screen cells and reports whether the pointer is over it; `at(x, y) (id, ok)` finds the spot under a cell (the last registered wins; for click dispatch); `hoverSpan(row, c0, c1)` is the look (underline, colours kept, trailing blanks untouched, a fresh underline after every SGR inside the span); `applyHover(h, rows)` underlines the spot under the pointer and every other spot with the same id (so an element spread over several rows registers one spot per row under one id and is hovered as a whole).
- Both views set `tea.MouseModeAllMotion` (motion without a button is needed). `screen()` runs `hv.begin()` first and `applyHover` last - not while the left button is held (a drag is a selection). The picker `View` does the same.
- Who registers: `listRows` -> `hotHeads` registers every visible head row of a tool block as `tool:<item>` (a wrapped head = several rows, all hovered together); the picker registers every readable row as `sess:<id>`. A new clickable element only needs `m.hv.add(id, screenY, x0, x1)` where it draws itself; the look and `at` come for free. Core registers its panel items this way.
- Invariant I-10 (`TestHover_MotionChangesNoState`): motion changes `sc`, `sel`, open blocks and the agent calls not at all; the plain text of the screen is identical.
- Readability: the underline carries no colour, so `TestReadable_HoverInEveryProfile` passes in 16 colours too. `hoverSpan` reuses `cellSpan` (whole graphemes) and `sgrRe` (colors.go).
- Gotcha: spots are registered by the draw, so a click right after a state change (before the next View) sees the spots of the previous frame - fine for the list (its clicks use `listPoint`, not `at`), relevant only for elements dispatched through `at`.

## Menu engine (`menu.go`, R-99) and the Session picker (`picker.go`)

One list engine for every picker of the app (T10). `menu{items []menuRow, vis, cur, top, filter, typing, w, h, title, hint, empty, chosen, confirm/ask/yes/onYes, note, hv, onChoose, onRight, keys, scopes/scope/onScope, parent}`; `menuRow{ID, Text, Match, Right, Dim}`: the host lays out `Text` (`columns()` pads cells), `Match` is what the typed filter searches (`Text` when empty; a `Dim` row matches only the empty filter), `Right` a right-aligned clickable label (`✕`, `on`, `off`, `approve`), `Dim` rows are dimmed and skipped. Standalone: `PickSession` runs the menu as a small alt-screen program (`menu.Update` maps every decision, `pickAction` `pickClose`/`pickChosen`, to `tea.Quit`). Embedded: `model.pick *menu` (set by `openMenu(mn, parent)`) takes the LIST AREA; `screen()` sizes it and draws `lines()`; `handleKey` and `update` route every key, mouse and wheel message to it first; `pickAct` applies the decision: `pickClose` -> `m.pick = parent` (a sub-menu returns to its parent, else closed), `pickChosen` -> `onChoose(id)` (true closes); an approval prompt (`askMsg`) closes the menu. Spots: `row:<id>` (the text), `right:<id>` (the label and its two blanks), `btn:yes` / `btn:no` (a confirmation, `confirmWith(ask, yesLabel, yes)`). Keys: Up/Down (k/j), PgUp/PgDn, Home/End, Enter chooses, Esc / q / Ctrl+C close, Tab cycles the save scope (`scopes`, footer `Tab scope: project`), host hotkeys in `keys` (`"ctrl+d"`, `"space"`, `"r"`, `"a"`, `"left"`, `"right"`; a letter is a command until filtering starts, `/` starts it), Backspace / Ctrl+U edit the filter; the wheel scrolls. `setItems` keeps the cursor on the same id. Footer: hints (+ scope), a confirmation `ask   [y] label   [n] cancel`, the last `note` (`note   (hints)`), `empty` for no rows, `nothing matches` for a filter without rows. `lines()` never returns more than `h` rows and registers spots only for the rows it returns.

Session picker (`picker.go`): `newPicker(rows []PickRow, current, del) *menu` is the first host (`sessionPick`): rows `started (local)  model  N msgs  title`, `(current)` marked, `✕` as the Right label when deletable (deleter wired, not current); Ctrl+D or the label asks `delete session <title>?   [y] delete   [n] cancel`, `y` or the button deletes through `del`, drops the row and keeps the cursor near (`selectNear`); a delete error stays in the footer; `the current session cannot be deleted` (R-34); unreadable rows are `Dim` `(unreadable)`. `openPicker` sets `onChoose = openSession`. Tested through `menu.Update` with synthetic messages (`picker_test.go`, `menus_test.go`) and the rig (`sessions_app_test.go`).

Menus (`menus.go`, T10): `/skills` -> `skillsMenu` (`◉/○ name  source  description`, Right `on`/`off`; Enter applies the Skill like `/skill name`, Space / the label switches it through `SkillsAPI.SetEnabled(name, on, scope)`, Tab cycles the scope); `/mcp` -> `mcpMenu` (`name  state  N tools  transport  source  reason`, Right `on`/`off` or `approve`; Enter opens `mcpServerMenu` (tools, `read-only` / `not offered` dim, the stderr tail as the note; Esc back), Space / label switches, `r` restarts, `a` / label approves (`MCPAPI.Approve`)); `/mcp <server>` opens the server menu directly; `/model` -> the fetched ids in `modelMenu` (the one in use marked; Enter sets; `/model N` keeps working from `modelList`); `/think` -> `thinkMenu` (two rows); `/config` -> `configMenu` over `ConfigAPI.Settings()` (`label  value  scope`; Enter / Space toggles a bool or opens the model menu for the model row, Left/Right step an int within Min..Max; every change goes through `ConfigAPI.Set(scope, key, value)` and is applied live for `Live` = `auto` (Approver), `think`, `model`, else the note says `at the next start`). `saved(scope, what, err)` builds the footer notes: `(saved to project)`, `(this run)` without a scope, `(this run only; not saved: <reason>)` on a `NotSavedError` (the switch applied, the write failed); rows are rebuilt after every action. `Deps.Scopes` (`ScopesAPI{Scopes, Default}`) and `Deps.Config` are optional: without Scopes a switch applies to this run only and no scope is shown; without Config `/config` says `settings are not available here`. ## Task blocks (`task_view.go`, `conv_render.go`, T4 A1/A3)

- No new item kind: the `task` call is an ordinary tool block (`● task(<goal>)  #N`, `└ <line 1 of the result>`, the whole TaskResult as its output when open). The work of the Task is folded under it on the flat list: `convItem.depth` (0 = Session) and `.parent` (list index of the Task block, -1 = none).
- Stack: `model.tasks` = list indexes of the running Task blocks, outermost first. `EvTaskStarted` pushes `runningByID(ev.Call.ID).item` (the block was added by the call's `EvToolStart`, at the depth of the caller), `EvTaskEnded` pops; both finish the live assistant item first so the Session's next text does not extend a child's. `model.place(i)` nests every item added while the stack is not empty (assistant text, tool blocks, notices): `depth = len(tasks)`, `parent = top`. A refused `task` call never gets `EvTaskStarted` and stays an ordinary block. `abandonCalls` (Turn end), `/clear` and a session switch drop the stack. Deltas, tool events, speed and progress inside a Task go through the same handlers; `EvMeter` with `Task != ""` is ignored (the panel shows the Session's meter).
- Folding: `conv.hidden(i)` = any ancestor Task block closed (Task blocks start closed, so the work is folded by default). A hidden item has zero rows (`itemCache.hidden` is part of the cache key); a hidden LIVE assistant item returns before rendering, so its committed-block cache (`blk*`) survives. Toggling a Task block invalidates the prefix sums from it on (descendants follow it in the list); `rowAt/toggle/setOpen/tailRows/itemAtRow` are unchanged, zero-row items are safe. `conv.openAncestors(i)` is used by Ctrl+O and `/tool N` for a hidden target.
- Gutter: an item at depth d is rendered `d*gw` cells narrower (`gw` = width of `taskGutter` = `"  │ "`) and every row gets d gutters after `splitMarks`; `lead` grows by `d*gw`, so `rowText` drops the Task gutters first and then the tool-block gutter (a copy holds neither). Hover spots of block heads start after the gutters (`hotHeads`); a click anywhere on a head row still toggles.
- The result line of a done `task` block sits right under its head (`resultLeads` in `live.go`: done preview or done task block; when open the report follows it as output rows), so the children that follow in the list stay below head + result. Unlike a shell preview, a closed task block shows no output lines.
- Progress line: `spinnerWork` lists the running Tasks, then the calls inside the innermost one: `Running task(fix tests) › shell(go test)…`, `› 2 tools…`. Approval prompt: `askPrompt(call, jobs, task)` names the asking Task: `Allow shell (task: fix tests): rm x?` (`Deps.Approve` is unchanged; the goal is `taskGoal()`).
- `/task <goal>` (`KindTask`, `parseTask`, `usage: /task <goal>`): through the optional agent part `taskSubmitter{SubmitTask(goal) error}` (a fake without it counts as Tasks off). `agent.ErrTasksOff` -> notice `tasks are off (tasks.max_depth)`; another error -> `task: <err>`; success -> Waiting Message with the goal (`EvTurnStarted` carries the goal, so `takeWaiting` matches).
- Plain mode: deltas with `Task != ""` are not printed; `EvTaskStarted` -> `[task: <goal>]`, `EvTaskEnded` -> `[task <line 1>]`; tool lines inside a Task are indented two spaces per level (a depth counter from the Task events).
- Resume (`rebuild`) adds no nesting: the parent history's `task` call shows as a closed block with its report.
